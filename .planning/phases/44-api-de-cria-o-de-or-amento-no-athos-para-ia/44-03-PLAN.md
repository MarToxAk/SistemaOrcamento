<objective>
Proteger a criação de orçamento contra duplicata quando a IA repete a chamada (header `Idempotency-Key`) e registrar no banco do Sistema cada orçamento criado pela IA (auditoria), com a reserva da chave feita antes de tocar o Athos.

Purpose: agentes de IA repetem requisições (timeout, retry, alucinação); sem idempotência cada repetição vira um orçamento novo no Balcão. A auditoria permite saber o que a IA criou e localizar órfãos se o Sistema falhar depois do COMMIT no Athos (D-03, Pitfall 8 da pesquisa).

Output: model Prisma `AthosOrcamentoIa` + migration aditiva, `AthosOrcamentoIdempotenciaService` (+ testes com Prisma falso), controller lendo o header, teste HTTP do controller e IT no clone provando o replay sem duplicata.

Requisitos: ORC-09, ORC-10 (tabela de IDs locais em 44-01-PLAN.md).
</objective>

### Serviço `apps/backend/src/modules/integrations/athos/athos-orcamento-idempotencia.service.ts`

```typescript
export const IDEMPOTENCY_KEY_REGEX: RegExp;                 // /^[A-Za-z0-9._:-]{8,128}$/
export function hashPayloadOrcamento(payload: unknown): string; // sha256 hex do JSON canonico (chaves ordenadas, recursivo), sem a chave "simular" do topo
export function refDoOrcamento(base: string): string;           // 12 primeiros hex de sha256(base)
export type ResultadoComReplay = CriarOrcamentoResultado & { replay?: boolean };

@Injectable() export class AthosOrcamentoIdempotenciaService {
  constructor(prisma: PrismaService);
  executar(
    idempotencyKey: string | undefined,
    payload: CriarOrcamentoInput,
    criar: (opts: { ref?: string }) => Promise<CriarOrcamentoResultado>,
  ): Promise<ResultadoComReplay>;
}
```

Fluxo de `executar`: (1) `payload.simular === true` -> `criar({})` direto, sem Prisma; (2) chave presente e inválida -> 400 `IDEMPOTENCY_KEY_INVALIDA` sem Prisma; (3) `payloadHash`; `ref` = `refDoOrcamento(chave ?? payloadHash)`; (4) com chave: `create` da reserva `{ idempotencyKey, payloadHash, status: "processando", request }`; erro com `code === "P2002"` -> `findUnique` pela chave: `status === "criado"` e mesmo hash -> devolver `resposta` salva com `replay: true` (sem chamar `criar`); hash diferente -> 409 `IDEMPOTENCY_KEY_REUTILIZADA`; senão -> 409 `IDEMPOTENCY_EM_PROCESSAMENTO`; (5) `criar({ ref })`; se lançar e houver reserva -> `delete` da reserva (erro do delete só é logado) e relançar o erro original; (6) sucesso: com chave -> `update` da reserva para `criado` + ids/valores/resposta; sem chave -> `create` da linha de auditoria com `idempotencyKey: null`; qualquer falha nesse passo -> `logger.error` com idorcamento e ref, e a resposta é devolvida mesmo assim.
