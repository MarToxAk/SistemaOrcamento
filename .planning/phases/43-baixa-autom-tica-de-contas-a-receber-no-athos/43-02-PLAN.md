<objective>
Calcular os encargos de atraso (juros, multa, atraso) exatamente como o Athos, a partir de `conf_financeiro`, e decidir o valor efetivamente gravado em `conta_recebida` e `livro_registro_io` comparando com o valor pago informado pela EFI. A formula e validada por TDD contra casos reais do proprio Athos coletados em modo somente leitura.

Purpose: o plano 43-01 so baixa titulo em dia (atraso maior que zero e rejeitado sem escrever). Este plano remove essa limitacao com o requisito BX-06 (D-02) sem chutar formula: o checkpoint de introspeccao traz a configuracao real e dezenas de baixas com atraso calculadas pelo Athos, e o teste exige reproduzi-las.

Output: `43-INTROSPECCAO-ATHOS.md` preenchido com "Decisoes derivadas", `athos-baixa-encargos.util.ts` (puro, com testes dourados), leitura de `conf_financeiro` na transacao da baixa, `extrairDadosPagamentoEfi` com valor pago, e decisao de valor com falha segura.

Decisoes de interpretacao deste plano (a confirmar pelo usuario - D-02 e ambigua quando a EFI so cobra o valor nominal): a regra de tres ramos acima. Ela honra "valor efetivamente pago" (o caixa nunca registra dinheiro que nao entrou) e "encargos calculados como o Athos" (quando o cliente realmente pagou com encargos ou quando a EFI nao informa o valor).
</objective>

```typescript
export interface ConfFinanceiroEncargos { taxaJurosMes: number; carenciaDias: number; percentualMulta: number }

// Nomes das colunas de conf_financeiro (identificadores FIXOS, usados em SQL). taxaJurosMes e carenciaDias vem da
// referencia capturada; percentualMulta e confirmado/definido por 43-INTROSPECCAO-ATHOS.md (Decisoes derivadas).
export const CONF_FINANCEIRO_COLUNAS: { taxaJurosMes: string; carenciaDias: string; percentualMulta: string };

export const TOLERANCIA_PAGAMENTO_PADRAO = 0.1; // R$, comparacao com o valor pago da EFI

export function diasEntre(inicioISO: string, fimISO: string): number; // dias corridos entre duas datas YYYY-MM-DD (UTC); negativo se fim anterior ao inicio

export function calcularEncargosTitulo(input: {
  principal: number; vencimento: string; dataPagamento: string; conf: ConfFinanceiroEncargos;
}): { atraso: number; juros: number; multa: number }; // atraso <= 0 -> tudo zero; arredondamento em centavos conforme a formula validada

export type ModoValorBaixa = "com_encargos" | "nominal";
export interface TituloValorBaixa { idcontareceber: number; principal: number; juros: number; multa: number; atraso: number; valorPago: number }

export type DecisaoValoresBaixa =
  | { ok: true; modo: ModoValorBaixa; titulos: TituloValorBaixa[]; valorTotal: number }
  | { ok: false; codigo: "VALOR_INCOMPATIVEL"; mensagem: string };

export function decidirValoresBaixa(input: {
  titulos: Array<{ idcontareceber: number; principal: number; vencimento: string }>;
  dataPagamento: string; conf: ConfFinanceiroEncargos;
  valorPagoEfi: number | null; tolerancia?: number;
}): DecisaoValoresBaixa;
```

### Alteracoes no servico de baixa (plano 43-01)

- `BaixaAthosCodigo` ganha `"VALOR_INCOMPATIVEL" | "CONFIG_ATHOS_INCOMPLETA"` e perde `"ATRASO_REQUER_ENCARGOS"`.
- `BaixarTitulosInput` ganha `valorPagoEfi?: number | null` (reais). `BaixarTitulosResultado` ganha `modo: ModoValorBaixa`.
- Leitura de configuracao (apenas quando algum titulo a baixar estiver em atraso), na mesma conexao e transacao, antes de qualquer escrita; a lista de colunas vem so de `CONF_FINANCEIRO_COLUNAS`:

```sql
SELECT <taxaJurosMes>, <carenciaDias>, <percentualMulta> FROM conf_financeiro LIMIT 1;
```

- A comparacao com `valorPagoEfi` so ocorre quando TODOS os titulos serao baixados (se algum ja estiver REC, o valor da EFI cobre titulos que o servico nao grava e a comparacao e ignorada).

### Orquestrador (plano 43-01)

`DadosPagamentoEfi` ganha `valorPago: number | null` e `fonteValor: string` (`'payment.paid_value'` ou `'nao_informado'`). `extrairDadosPagamentoEfi` le `payment.paid_value`; a EFI expressa valores monetarios em centavos inteiros (mesma convencao dos itens enviados em `criarBoleto`), entao `valorPago = paid_value / 100`; valor ausente, nao numerico ou menor ou igual a zero devolve `null`. `executarAposPagamento` repassa `valorPagoEfi` ao `baixarTitulos` e inclui `fonteData` e `fonteValor` no log de sucesso.
