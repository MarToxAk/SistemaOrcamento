## E2E Flow Verification

**Complete:** 1/1 — GET (list) → POST (add) → PATCH (edit quantity) → DELETE (remove) → `usaprodutocomposto` flag toggling, traced through actual code:
- Flag turns `true` on first component add (`adicionarComponente`, same `BEGIN/COMMIT` as the INSERT).
- Flag turns `false` on last component removal (`removerComponente`, same `BEGIN/COMMIT` as the DELETE).
- Flag visibility closes the loop via `GET /athos/produtos/:idproduto` (`athos.service.ts::buscarProdutoPorId`), which returns the full `produto` row including `usaprodutocomposto` — an operator reading the master product after a write sees the current composition state.

**Broken:** 0.

## Error-Path Verification (GRANT-missing gate)

`mapPgWriteError` maps Postgres `42501` (permission denied) to an actionable `500` naming the exact GRANT statements needed. Both `adicionarComponente` and `removerComponente` `ROLLBACK` before mapping the error — no partial commit possible when the GRANT is missing. `atualizarQuantidade` is a single autocommit statement with the same error mapping. Covered by existing tests (`athos-produto-composto.service.test.ts`).
